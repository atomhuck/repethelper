# RepetHelper

## Приглашения учеников

Код приглашения преподавателя создаётся один раз и не меняется: он безопасно используется в постоянной ссылке вида `https://repethelper.ru/invite/T-XXXXXXXX`. В кабинете преподавателя можно скопировать как код, так и ссылку. Переход по ссылке не даёт доступа к данным: ученик должен войти или зарегистрироваться и нажать «Отправить запрос», после чего преподаватель вручную принимает запрос.

В списке учеников доступно удаление с отдельным подтверждением и предварительным подсчётом данных. Удаляется только связь с этим преподавателем, все его занятия, серии, вложения и доски; сам аккаунт ученика сохраняется и может быть использован позднее.

У каждого принятого ученика есть отдельная карточка преподавателя: ближайшее занятие и его домашняя работа, материалы последней проведённой встречи, файлы и полная история занятий. Преподаватель может хранить необязательное описание ученика, отдельную личную заметку к каждому уроку и отмечать сдачу домашней работы состояниями «не отмечено», «сдал» или «не сдал». Эти записи привязаны к конкретной паре «преподаватель–ученик», не показываются ученику и не отправляются в email-уведомления.

## Финансы преподавателя

Раздел `/teacher/finances` показывает ожидаемый и полученный доход по календарным месяцам, детализацию занятий и просроченные неоплаченные встречи. Доход относится к месяцу проведения занятия; занятия без цены и отменённые неоплаченные встречи в расчёты не входят. Оплату можно отметить прямо в разделе и безопасно отменить сразу после изменения.

Оплаченная сумма сохраняется в обезличенной финансовой записи даже после удаления занятия или связи с учеником. Синхронизация статуса занятия и финансовой истории выполняется транзакционным PostgreSQL-триггером. Финансовые сведения доступны только преподавателю-владельцу и не попадают в ученические страницы, письма или данные доски.

### Абонементы

Преподаватель может создать для конкретного ученика пакет из 1–100 заранее оплаченных занятий. Общая сумма распределяется по местам в целых рублях без потери остатка, а несколько пакетов используются по FIFO. Занятие резервирует одно место и остаётся обычной оплаченной строкой в месяце его проведения; ручная цена и ручной статус оплаты при этом блокируются до возврата места в баланс.

Обычное удаление возвращает место, перенос сохраняет его, а отдельное подтверждаемое действие «Списать как пропуск» после начала встречи сохраняет доход и не возвращает занятие. Ученик видит только доступный и запланированный остаток по преподавателям — стоимость пакетов и финансовые действия остаются приватными. Функция управляется переменной `APP_SUBSCRIPTIONS_ENABLED`.

## VK ID

Вход через VK отключён по умолчанию. Создайте веб-приложение в кабинете VK ID, укажите callback `https://repethelper.ru/login/oauth2/code/vk` и задайте на сервере в `.env.production`:

```env
APP_VK_AUTH_ENABLED=true
VK_CLIENT_ID=...
VK_CLIENT_SECRET=...
VK_REDIRECT_URI=https://repethelper.ru/login/oauth2/code/vk
```

Секрет VK не добавляйте в Git и не отправляйте в чат. После развёртывания появится кнопка «Продолжить с VK»; обычный вход по паролю остаётся доступен для аккаунтов, созданных через стандартную регистрацию.

После успешного входа RepetHelper сохраняет защищённую сессию на устройстве: закрытие вкладки или браузера не требует повторного входа. Сессия прекращается после 30 дней бездействия, при явном выходе, смене пароля или отключении аккаунта.

При первой авторизации через VK пользователь выбирает только роль — преподаватель или ученик. Имя и подтверждённый email берутся из VK, а внутренний уникальный логин создаётся автоматически. При следующих авторизациях тот же VK ID сразу открывает кабинет. Аккаунт, созданный через VK, не получает пароль и не может войти через обычную форму или восстановление пароля. Если email из VK уже занят аккаунтом стандартной регистрации, автоматическое объединение не выполняется: пользователь получает сообщение о конфликте. Осознанно привязать VK к обычному аккаунту можно только после входа в разделе безопасности аккаунта.

Теперь у каждого занятия есть отдельная совместная бесконечная доска. Преподаватель и назначенный ученик могут одновременно рисовать, видеть курсоры друг друга, стирать целые штрихи, загружать и трансформировать фотографии, перемещаться по рабочему полю и менять масштаб. Доска сохраняется в PostgreSQL и восстанавливается после перезапуска приложения.

### Технологии realtime-доски

В обновлённой доске доступны текстовые объекты, рамочное выделение штрихов, текста и изображений, пакетное перемещение и объектный ластик. Undo/Redo хранит до 100 собственных действий текущей вкладки; удалённые объекты можно восстановить в течение двух часов. На компьютере доступна история заполненных досок ученика и переименование, а на телефоне используется компактная панель из пяти инструментов. Горячие клавиши: `P` — карандаш, `V` — выбор, `E` — ластик, `T` — текст, `H` — рука, `Ctrl/Cmd+Z` — Undo, `Ctrl/Cmd+Shift+Z` — Redo.

- Spring WebSocket без STOMP и внешнего брокера — двусторонняя синхронизация двух участников внутри монолита.
- Fabric.js 7.4.0 — объектная модель canvas, свободное рисование, изображения, pan и zoom. Зафиксированная сборка и MIT-лицензия находятся локально в проекте, CDN не используется.
- JSONB в PostgreSQL — хранение геометрии штрихов и трансформаций изображений; каждая подтверждённая операция увеличивает ревизию доски.
- Сессионная аутентификация Spring Security — HTTP и WebSocket используют одну авторизованную сессию. UUID доски служит адресом, но не даёт доступ сам по себе.
- Изображения декодируются и повторно кодируются на сервере, очищаются от метаданных и хранятся в том же закрытом Docker-томе, что и остальные вложения.

Доска рассчитана на один экземпляр приложения. Для нескольких экземпляров в будущем потребуется общий канал событий, например Redis Pub/Sub, и общее файловое хранилище.

Многопользовательский кабинет преподавателей и учеников: каждый преподаватель получает уникальный код приглашения, управляет только своими учениками, планирует разовые или еженедельные занятия и прикладывает домашние задания и материалы.

Еженедельная серия не имеет фиксированной даты окончания: новые встречи появляются автоматически по мере просмотра будущих месяцев. Любое занятие серии можно перенести отдельно либо применить изменение к нему и всем последующим встречам. При удалении можно убрать только выбранную встречу или остановить серию с неё —удалённые занятия не остаются в календаре и истории.

## Стек

Проект сделан как серверный монолит на Java:

- Java 21 и Spring Boot 4.1 — основа приложения, конфигурация и запуск.
- Spring MVC — обработка страниц, форм, загрузки и скачивания файлов.
- Thymeleaf — серверный рендеринг HTML-шаблонов без отдельного frontend-приложения.
- Spring Security — сессионная аутентификация, BCrypt-хеширование паролей, CSRF-защита и разграничение доступа по ролям `TEACHER` и `STUDENT`.
- Spring Mail — подтверждение email и одноразовое восстановление пароля через SMTP Яндекс 360.
- Hibernate и Spring Data JPA — работа с доменными сущностями: пользователями, профилем преподавателя, заявками, занятиями и вложениями.
- PostgreSQL — основная реляционная база данных.
- Flyway — версионированные миграции схемы БД. Hibernate работает в режиме `validate` и не меняет структуру базы самостоятельно.
- Docker Compose — локальный запуск приложения вместе с PostgreSQL.
- Testcontainers, JUnit 5 и MockMvc — интеграционные и веб-тесты с настоящим PostgreSQL в контейнере.

Вложения хранятся вне публичной директории приложения: в Docker-томе или локальном каталоге, заданном настройками. Скачивание всегда проходит через контроллер, который проверяет права текущего пользователя.

## Быстрый запуск

1. При необходимости скопируйте `.env.example` в `.env` и смените пароль преподавателя.
2. Запустите приложение:

   ```bash
   docker compose up --build
   ```

3. Откройте [http://localhost:8080](http://localhost:8080).

Значения по умолчанию для первого входа преподавателя:

- логин: `teacher`
- пароль: `change-me-now`
- код подключения: `teacher_code`

Перед использованием обязательно задайте собственный `TEACHER_PASSWORD` в `.env`. Отображаемое имя и код подключения можно изменить в кабинете.

## Разработка

Понадобятся Java 21+, Maven и PostgreSQL. Параметры подключения и каталог вложений задаются переменными из `application.yml`. Сборка и тесты:

```bash
mvn test
```

Flyway применяет схему автоматически. Hibernate работает в режиме `validate` и не изменяет структуру базы самостоятельно.

## Ограничения файлов

К домашнему заданию и материалам занятия можно приложить до 5 файлов размером не более 15 МБ каждый. На доске разрешено до 30 изображений JPEG/PNG по 10 МБ, до 4096 px по длинной стороне и до 150 МБ на доску. Исполняемые типы блокируются, а скачивание доступно только преподавателю и ученику, которому принадлежит занятие.

## Аккаунты и почта

Ученики и преподаватели регистрируются самостоятельно. Логин и email уникальны без учёта регистра, войти можно по любому из них. Пароли хранятся как BCrypt-хеши. Подтверждение email и сброс пароля выполняются шестизначными одноразовыми кодами: код действует 15 минут, блокируется после пяти неверных вводов и хранится в БД только как BCrypt-хеш.

Один ученик может подключиться к нескольким преподавателям по их кодам или ссылкам-приглашениям. Расписание ученика объединяет занятия всех преподавателей, при этом каждый преподаватель видит и изменяет только собственные занятия, серии, файлы и доски.

Сервис отправляет через надёжную очередь PostgreSQL уведомления о заявках, создании, переносе и удалении занятий, обновлении домашней работы и напоминания за четыре часа. Временная ошибка SMTP не откатывает пользовательское действие: письмо повторяется фоновым обработчиком. Для еженедельной серии отправляется одна сводка, а напоминания создаются для каждой фактической встречи.

Локально отправка писем отключена. В production нужно создать доменный ящик Яндекс 360 и заполнить `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_FROM` и `MAIL_REPLY_TO` в серверном `.env`. Коды подтверждения и сброса не записываются в журнал приложения, реальные почтовые пароли нельзя добавлять в Git.

Старые аккаунты после обновления один раз указывают email и принимают актуальные документы. Политика обработки данных, согласие и пользовательское соглашение доступны в разделе `/legal`.

Юридические страницы являются рабочими шаблонами для текущего набора функций. Перед активными продажами их нужно проверить у профильного юриста и отдельно подать уведомление об обработке персональных данных в Роскомнадзор. Полный домашний адрес в код и публичные страницы не добавляется.

## Публичный сервер

Для production используется отдельная конфигурация `compose.production.yaml`:

- готовый Docker-образ загружается из GitHub Container Registry;
- PostgreSQL и приложение доступны только внутри Docker-сети;
- Caddy публикует сайт на `80/443`, автоматически получает TLS-сертификат и проксирует WebSocket;
- приложение работает с защищённой cookie и точным списком разрешённых WebSocket Origin;
- healthcheck недоступен через публичный домен;
- база, вложения и сертификаты сохраняются в постоянных Docker-томах.

Push в `main` запускает тесты и публикует образы `main` и `sha-<commit>`. Сервер не обновляется автоматически: конкретный SHA разворачивается командой `ops/deploy.sh`, которая сначала создаёт резервную копию и возвращает предыдущую версию при неуспешной проверке.

Полная инструкция по подготовке Ubuntu 24.04, SSH, домену, HTTPS, Yandex Object Storage, обновлениям, восстановлению и таймерам находится в [production runbook](ops/README.md).
